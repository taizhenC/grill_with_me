# Room capability safety — 2026-10-02

Plan: P0-03, room capabilities and collision safety. Branch: `codex/room-capability-safety`.

## Implemented

New rooms use `r_` plus 32 lowercase hexadecimal characters generated by
`crypto.randomBytes(16)`: 128 random bits. The server, browser, and packaged CLI
use the same validator. Malformed keys are rejected before storage access or
CLI network requests. Room references remain case-sensitive; no weak alias is
created for a new key. The npm archive includes the shared runtime helper.

Existing word-word-number links still access their original rows until the
original 30-day expiry, including authenticated republish and informational
claims. Republish preserves that expiry. Publish a new room to replace a legacy
link with a stronger one; compatibility does not strengthen legacy keys.

Both stores retry creation at most five times. Memory collisions preserve all
existing content, tokens, claims, and timestamps, even for expired rows still
stored. Supabase retries only PostgreSQL `23505` with the exact standard error
message naming `rooms_key_key`, the existing unique constraint on `key`.
`rooms_pkey` belongs to UUID `id` and is never treated as a key collision.
Unrecognized constraints, permissions, and other errors fail immediately.

Room pages and the room API send `X-Robots-Tag: noindex, nofollow, noarchive`,
`Referrer-Policy: no-referrer`, and private `no-store` cache controls. Member and
host metadata also use `noindex, nofollow`. These controls apply to errors too.

## Limits and follow-ups

This slice does not complete P0-03: shared abuse quotas, trusted origin handling,
and bounded mutation reads are separate work. Links remain bearer access, and
claims remain informational. Anyone holding a valid link can access its room.
Legacy links retain their weaker entropy until their existing expiry.

No database migration, real Supabase execution, deployed CDN behavior, public
deployment, or npm publication was performed here. Database collision behavior
is verified against controlled HTTP responses. A custom database constraint name
or localized message fails safely without a retry. Hosted Windows/Linux CI is
required before merge; no merge has been performed by this feature task.
