# Live-agent evaluation kit

This kit measures the current installed member instructions with real account-local agents. It never calls a mocked model. CI tests fixture construction, bounded process handling and evidence handling; those tests do not establish agent behavior or filesystem confinement.

Install repository dependencies, authenticate your local Claude Code or Codex CLI yourself, and run from this repository with Node 24:

```sh
node scripts/run-agent-evals.mjs --agent claude --out evals/runs/NEW-RUN/claude --case member-frontend
node scripts/run-agent-evals.mjs --agent codex --out evals/runs/NEW-RUN/codex --case member-frontend
```

Omit `--case` for the nine-case matrix, or supply comma-separated case IDs for a bounded subset. Each agent has five member cases (two fresh CLI processes per case, with the previous answer replayed verbatim), three clean checks, and one seeded check. Each run has a 14-call / 30-minute ceiling; each invocation has a 120-second, 2 MiB output ceiling. Claude also receives a USD 1 per-call estimated-cost cap. The runner stops on errors or quota failures and never retries automatically. A quota warning alone is not authorization to bypass a limit. A new output directory is mandatory; reruns must have separate records.

On Windows the default local executable locations match the account-local installers. Override `--claude-bin PATH` or `--codex-entry PATH` when needed; the latter is the installed `@openai/codex/bin/codex.js` entry point, launched with the same Node executable as the runner. Linux/macOS require `--codex-entry PATH`. No model is selected by the kit: record the actual model from runtime evidence. Codex JSON does not always expose a model ID; a preflight CLI header can document the observed default, but must not be presented as a per-call model assertion.

Fixtures live in a fresh system temporary directory. Member cases use the current `lib/pack.ts` renderer and actual CLI install planner/executor, including the local role, receipt, AGENTS block, command and member skills. Agents enter through AGENTS and the installed command's file references. This is explicit instruction-path execution; restricted Claude disables native slash-command discovery, and Codex reads the `.claude/commands` file through the supplied adapter instruction. It does not test a user's native editor discovery or global skill configuration.

Drift fixtures use the actual copied CLI's `contract-finalize` commands to create a valid source snapshot, stable agreement blocks and revision history. Amended cases finalize an explicit child amendment; current CONTRACT.md already contains the items wrapper. `contract-status` must report fresh with no pending roles before a fixture can run. The agent gets the same copied offline status command and actual check skill. These are prose-only fixtures; they do not establish consuming TypeScript integration, which has its own real project checks.

Claude uses restricted file tools and an explicitly listed offline Node validation command, empty strict MCP configuration, no saved session and no project/user settings. Runtime evidence shows the CLI also permits some directory-local read commands such as `ls`/`cat`; the requested allowlist is not an exclusive command gate. Codex uses an ephemeral workspace-write sandbox, ignored user configuration/rules, disabled search and sandbox network, no approval requests, and Windows' supported `unelevated` sandbox mode. It now disables the known external user grilling skill per invocation after original runs read it despite the fixture-only prompt; one corrected Frontend subset complied with the requested read scope, recorded separately from the original matrix. Ignoring user configuration does not disable globally discovered skills, and workspace-write does not confine filesystem reads. The stricter named-profile smoke was unsupported by the local Windows unelevated backend. Authentication stays in each CLI's own local runtime; do not copy it into this repository or public CI. The scripted prompts forbid external reads and writes. This harness is not an operating-system security proof for arbitrary untrusted agents; review traces for scope violations. Passing write-scope checks is never evidence of read confinement.

Records include frozen fixture inputs, hidden grading expectations, exact prompts and arguments, selected tool/results/assistant events, timing, version, usage, the first observed/authored spec, final artifact and deterministic validation. Hidden expectations are outside the agent's fixture. Reasoning, signatures, account identifiers, auth metadata and quota percentages are omitted; paths are redacted. Review committed evidence for accidental private content. Temporary fixtures are retained locally for investigation; remove only the specific `grill-agent-eval-*` directory you created after review.

`first-artifact.md` comes from the first Claude Write tool payload when available. Codex uses the first nonempty file observed at 10 ms intervals; inspect its trace to ensure there was one creation and no intervening repair. A fast intermediate write may evade this observer, so unsupported first-pass claims remain unknown. `artifact.md` is the final handed-off file. Separate prompt repairs/forced response schemas from these unassisted measurements.

Grade behavior manually using [the rubric](rubric.md). A valid heading structure alone does not show factual agreements, usable questions or correct drift. Commit dated evidence and a completion report under `doc/` even when a gate fails. The [human pilot worksheet](../doc/team-pilot-worksheet.md) is a separate release gate.

Implementation references: [Claude programmatic runs](https://code.claude.com/docs/en/headless), [Claude CLI reference](https://code.claude.com/docs/en/cli-reference), [Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode), [Codex Windows configuration](https://learn.chatgpt.com/docs/config-file/config-reference), and [OpenAI's skills-evaluation guidance](https://developers.openai.com/blog/eval-skills). Local `--help` takes precedence when installed flags differ.
